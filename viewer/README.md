# Local graph viewer

This directory contains a small, static viewer for the FRBR graph.  It is a
local inspection tool; the public viewer generated by the MeLODy template is
not changed.

## Start the viewer

From the repository root:

```bash
python3 tools/viewer_data.py          # writes viewer/data/nodes.jsonl and edges.jsonl
python3 -m http.server 8000
```

Then open <http://localhost:8000/viewer/>.

The page must be served over HTTP.  Opening `viewer/index.html` directly with
`file://` does not work because the information panel fetches the entity
Turtle files.

The Python script needs `rdflib` (the same dependency as
`tools/datasets.py`).  If the repository uses a virtual environment, call it
through that interpreter instead.

The graph files are generated from the entity folders and checked in so that
the viewer works immediately.  Regenerate them after an ingest batch:

```bash
python3 tools/viewer_data.py
```

## What the tree contains

The solid tree follows the direction needed to read the acervo:

```text
Person (composer) → Work → Expression → Manifestation → Item
```

It also supports a person's arranger and librettist roles when the expression
is not already reachable below one of that person's composed works.  Work,
expression, manifestation and item parts are included as child branches.

Everything else is a dashed cross-link.  For example, the copyist of an item
is a cross-link from the item to the person; it is not a second child of the
person.  Clicking a node does not re-centre or rebuild the graph.

The arrowheads follow the RDF direction of the underlying edge, which is not
always the same as the readable tree direction: `lrmoo:R4_embodies` goes from
Manifestation to Expression, and `lrmoo:R7_exemplifies` goes from Item to
Manifestation.  The tree draws the reverse direction for readability; the
legend says so.

## Interactions

- **Click** a node to show its complete Turtle record in the side panel.
- **Double-click** a node to collapse or expand its children.
- The `+` / `−` control on a node does the same.
- **Drag** a node to move it.  Use the background to pan and the wheel to zoom.
- **Expand all** / **Collapse all** work from the current root.
- **Fit** brings the whole tree back into view.
- The search box accepts any part of a label or IRI.  Choosing a result makes
  that entity the new root.  The current root is stored in the URL hash, so a
  particular view can be bookmarked or shared locally.
- **Show as root** in the information panel re-roots the tree at the selected
  entity.

## Files

| file | function |
|------|----------|
| `index.html` | page shell and SVG |
| `styles.css` | layout and node styles |
| `app.js` | tree layout, drag/collapse interactions, search and metadata panel |
| `data/nodes.jsonl` | one node per entity |
| `data/edges.jsonl` | one typed relationship per line |
| `vendor/` | vendored D3 7 and N3 browser builds, with their licences |

`tools/viewer_data.py` fetches the full record only after a node is selected,
so the graph files stay reasonably small.  The information panel parses that
Turtle with N3 and renders every triple, including blank-node structures such
as titles, contributions and hands.
